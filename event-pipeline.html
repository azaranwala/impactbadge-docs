Event Aggregation Pipeline

5-source import system ensuring users always see volunteer events — deployed September 2026

Problem Solved

New users opening ImpactBadge saw no events because all events were created by org admins (who hadn't signed up yet). The aggregation pipeline imports events from external sources automatically, so every user sees volunteer opportunities from day one.

On-Demand Import

When a user opens the app, the client calls onDemandImportCall({ lat, lng }). The backend:

  1. Maps coordinates to the nearest of 20 major US cities
  2. Checks a cooldown grid (~11km cells, 6-hour cooldown per cell)
  3. If not recently imported, runs VolunteerMatch + SerpAPI in parallel for that city
  4. New events appear in the user's feed immediately

Cooldown tracked in Firestore collection: importCooldowns/{geoCell}

Dynamic Radius Expansion

getEventsNearbyCall enhanced with autoExpand: true parameter:

  • If fewer than 10 events found at requested radius, auto-expands
  • Expansion steps: 10 → 25 → 50 → 100 km
  • Response includes effectiveRadiusKm and autoExpanded flag
  • Fully backwards compatible (defaults: autoExpand=false)

SerpAPI Configuration

Engine: google (free tier, 250 searches/month)

Account: ops@impactbadge.app

Queries (8): volunteer events, community service, nonprofit events, charity events, food bank volunteer, cleanup events, animal shelter volunteer, habitat for humanity — all in Richmond VA

Category detection: Regex-based from title + event type (animals, hunger, environment, education, health, seniors, arts, community)

Deduplication

All imported events use a shared deduplication system in importHelpers.ts:

  • MD5 hash of title | date | address[:20]
  • Stored as dedupKey on each event document
  • Checked before every write — prevents duplicate imports across sources
