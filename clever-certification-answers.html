Brief Summary of Application
ImpactBadge is a K-12 volunteer hour tracking platform for students ages 11-18. Students discover volunteer events nearby, register, check in via GPS/PIN/QR code, log hours, earn XP and badges, and export verified transcripts for college applications (including Common App format). The platform supports iOS (native SwiftUI), Android (React Native), and a web dashboard for school and org admins.

3. District Onboarding Steps

1. What additional steps are required by the district?
No manual matching steps are required. When a district shares data with ImpactBadge through Clever, we automatically provision all student, teacher, and staff accounts. District admins do not need to complete any additional configuration — accounts are created and matched using Clever ID as the primary identifier.

2. Is an initialization sync required?
Yes. When a district first connects, we trigger an initial full sync that pulls all students, teachers, staff, schools, and sections in bulk via the Clever API. This runs automatically when the district is first enabled. After the initial sync, a daily full sync runs at 2:00 AM EST, and the Events API is polled every 15 minutes for incremental changes.

3. Who owns the onboarding/initialization sync process?
Our implementation team (ImpactBadge) owns the entire sync process. The district team only needs to share their data with ImpactBadge through the Clever dashboard. No action is required from the district's IT staff beyond the initial Clever sharing step.

5. SSO Integration

SSO Integration
Yes
Mobile SSO
iOS: The "Sign in with Clever" button opens the Clever OAuth authorization URL in an in-app browser (ASWebAuthenticationSession). After the user authenticates with Clever, Clever redirects to our Cloud Function endpoint (cleverOAuthCallback). The server exchanges the authorization code for an access token, fetches the user profile from Clever API v3.1, creates or matches the Firestore user record, generates a Firebase custom token, and returns it to the iOS app. The app exchanges the custom token for a Firebase Auth session via Auth.auth().signIn(withCustomToken:).

Android: The same flow applies. The "Sign in with Clever" button opens the Clever OAuth URL in Chrome Custom Tabs. The redirect is handled by our Cloud Function, which returns the Firebase custom token. The React Native app receives the token and calls auth().signInWithCustomToken(token) to establish the session.

Both platforms support the same redirect URI pattern and share the same backend Cloud Function (cleverOAuthCallback).
Identity Management
Firebase Authentication. We exchange the Clever authorization code for an access token server-side, then generate a Firebase custom token which the client uses to establish a Firebase Auth session. No external identity provider (Okta, Auth0, etc.) is used.
Auth Type
OAuth 2
Loading Behavior
Users see a centered loading spinner with the text "Signing you in with Clever..." on a clean white background. On mobile (iOS/Android), the same spinner is shown after the Clever OAuth redirect returns to the app. The loading state persists until the Firebase custom token exchange completes and the user's profile is loaded from Firestore (typically 1-3 seconds).
Error Handling
If authentication fails at any stage (missing authorization code, token exchange failure, invalid Clever response, Firebase token generation error), the user sees a centered error card with a red exclamation icon, the heading "Sign-In Failed", a descriptive error message, and a "Back to Login" button. On mobile, errors are displayed as native alert dialogs. Student accounts that attempt to access the web dashboard see a specific message: "Student accounts cannot access the web dashboard. Please use the ImpactBadge mobile app." All errors are logged server-side without PII.
Invalidate Previous Sessions
Yes — Each new Clever authentication generates a fresh Firebase custom token. On shared devices, the new login overwrites the existing Firebase Auth session.

6. Sync Configuration

Sync Methods
Nightly sync Sync button/sync on demand
Syncs Events (Events API)
Yes
Events Data Usage
We poll the Clever Events API every 15 minutes via a Cloud Scheduler (Pub/Sub) function (cleverEventsPoll). We use the starting_after cursor parameter to fetch only new events since the last poll. We process the following event types:

- students.created: Provision new student account in Firestore
- students.updated: Update student profile fields using non-destructive merge
- students.deleted: Set cleverArchived: true on the user record (preserve all data)
- teachers.created: Provision new teacher account with role "teacher"
- teachers.updated: Update teacher profile fields
- teachers.deleted: Archive teacher record
- staff.created / staff.updated / staff.deleted: Same as teachers, mapped to "school_admin" role
- sections.created / sections.updated / sections.deleted: Update section rosters in cleverSections collection

Each processed event ID is stored to prevent duplicate processing. Failed events are logged and retried on the next poll cycle.

7. Rollover

Outside of Clever: ImpactBadge tracks school year progress based on a configurable school year start date (stored in schoolSettings per school). Volunteer hours are cumulative across all years and are never reset. At year-end, student grade levels can be updated manually by school admins via CSV import. Students who graduate (grade 12) retain their full history for college transcript exports. Graduation compliance tracking resets expectations based on the new grade level.

With Clever integration: During daily roster sync, if a student's grade or school changes in Clever (as happens during summer rollover), we snapshot the student's previous state — school name, district name, grade, and total verified hours — to a schoolHistory subcollection before updating their profile. Each transition is recorded with a timestamp and reason code (year_end_rollover, school_transfer, or district_transfer). The student's accumulated volunteer hours, badges, XP, and transcripts are fully preserved and travel with them. Clever is treated as the source of truth for grade and school assignment. Section memberships from the previous year are marked active: false with a leftAt timestamp, and new section memberships are created for the new year.

9. User Experience by Role

District Admin User Experience
District admins have full school management access in ImpactBadge. They can view all students across their school with volunteer hours and compliance status, set graduation hour requirements, run compliance reports showing which students are on track/at risk/below minimum, bulk import students via CSV, configure school settings (school year start date, senior deadline, per-grade minimums), trigger manual Clever roster syncs, view district-wide reports, send announcements to all students, manage pre-approval requests for community service learning, and export compliance data as CSV. District admins access ImpactBadge through the web portal.
School Admin (Staff) User Experience
Staff and school admins have the same capabilities as district admins within their school scope. They can view their school's student roster with hours logged, badges earned, and compliance status. They can set and manage graduation volunteer hour requirements, review and approve/reject self-reported volunteer hours, run compliance reports with color-coded status, bulk import students via CSV, send school-wide announcements, configure school settings, and export student data. On mobile (iOS/Android), staff who log in via Clever SSO are routed to the school admin dashboard.
Teacher User Experience
Teachers have read-only access to student volunteer data through the Advisor Dashboard. They can view all students at their school with name, grade, total hours, hours remaining, progress bar, and compliance status (Seal Eligible, On Track, At Risk, Below). They can search students by name and export the student list as CSV. Teachers see summary statistics including total students, total hours, percentage on track, and participation rate. Teachers cannot modify graduation requirements, import students, change settings, verify hours, or send announcements. Teachers access ImpactBadge through the web portal via Clever SSO and are routed to the /advisor dashboard.
Student User Experience
Students use the ImpactBadge mobile app (iOS or Android) to discover volunteer events near them, register for events with waitlist support and multi-shift selection, check in via GPS/PIN/QR code, check out to log verified volunteer hours, self-report external hours with e-signature and photo evidence, view their hours dashboard with graduation progress, earn XP/badges/levels through gamification, compete on leaderboards, participate in school-vs-school challenges, chat with other volunteers, write reflections, and export verified hours as PDF certificates, college transcripts, Common App activities, and Naviance CSV. Students log in via Clever SSO or email/password/Google Sign-In.

Missing Fields Handling
We use graceful fallbacks for all non-guaranteed fields. If student email is missing (common with Clever Library), the account is created with a needsPersonalEmail flag and the student is prompted to provide a personal email on first login. If grade is missing, graduation year tracking is disabled for that student and they are excluded from grade-based compliance calculations. If teacher email is missing, the teacher account is created but cannot receive email notifications. No sync ever fails due to missing fields — all fields default to safe empty values and the user record is still created successfully.

11. Rosters & Sections

Uses Rosters
Yes — syncs teacher-student associations through sections records
Term Data Usage
No — ImpactBadge uses its own configurable school year start date rather than Clever term dates
Deleted Sections
When a section is deleted from Clever, we mark it as inactive in our cleverSections collection (active: false, deletedAt: timestamp). All student volunteer hours and progress data are fully preserved — hours belong to the student, not the section. Section membership records are updated with leftAt timestamp and active: false.
Un-enrolled Students
Students without sections have the same full experience in ImpactBadge. Section enrollment is used only for teacher-student association. Students without sections can still discover events, register, check in, log hours, earn badges, and export transcripts. They appear in school-wide compliance reports and are visible to school admins.
Multi-enrollment Students
Students enrolled in multiple sections have a single account in ImpactBadge. All section memberships are tracked in the sectionMemberships subcollection. The student appears on each associated teacher's student list. Their volunteer hours, badges, and compliance status are unified across all sections — there is no duplication or conflict.
Multi-site Students
Students associated with multiple school sites have a single account. Their primary school is set to the most recently synced schoolName from Clever. Previous school associations are recorded in the schoolHistory subcollection. Volunteer hours are cumulative across all schools and count toward graduation requirements at the current school.
Co-teacher Support
Yes, we support co-teachers. Sections store a teacherIds array that can contain multiple teacher Clever IDs. All co-teachers can view the students in that section. There is no limit to the number of co-teachers we support per section.
Teachers without Sections
Teachers without sections have a fully functional account. They can log in via Clever SSO and access the Advisor Dashboard, which shows all students at their school (not scoped by section). Section assignment is not required for teacher functionality.
Multi-section Teachers
Teachers with multiple sections have a single account. All section associations are tracked. In the current implementation, teachers see all students at their school rather than only students in their sections. The teacher's experience is the same regardless of how many sections they are assigned to.
Multi-site Teachers
Teachers associated with multiple school sites have a single account. Their primary school is set to the most recently synced schoolName from Clever. If a teacher transfers between schools via Clever roster update, their account is updated and the previous school is recorded in schoolHistory.

12. Deletion & Restoration

Deleted Records
When a record is deleted or unshared in Clever, our integration sets cleverArchived: true on the user's Firestore document. The user's data — volunteer hours, badges, XP, transcripts, and all historical records — is fully preserved but the account is marked as inactive. Archived users do not appear in school admin student lists or compliance reports. We never permanently delete user data as a result of a Clever sync.
Restoring Records
When a previously deleted or unshared record reappears in Clever with the same Clever ID, our integration matches on cleverUserId and sets cleverArchived: false. All previously accumulated data (hours, badges, XP, transcripts, section memberships) is immediately restored and visible. The user's account resumes normal functionality with no data loss.
